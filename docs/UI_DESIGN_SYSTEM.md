# 博邦 ERP UI 设计系统

版本：1.0
设计方向：方案 A「清晰实用」
适用范围：Vue 3 + Element Plus Web，以及复用相同入口的 Tauri 桌面端

## 1. 设计目标

博邦 ERP 是工厂内网中高频使用的数据工具。视觉设计的首要目标不是“展示感”，而是让办公室、仓库、生产部门和管理员在长时间操作中快速定位信息、减少误操作并清楚判断当前状态。

方案 A 遵循五项原则：

1. **任务优先**：页面标题、待办、筛选、主要操作和异常数据形成稳定层级。
2. **清楚胜过装饰**：保留品牌识别，不使用大面积渐变、玻璃拟态、装饰插画或无业务意义的图表。
3. **密度可控**：默认使用 40px 控件和 48px 表格行；超长档案列表可切换为 32px 控件和 40px 紧凑行。
4. **状态有冗余表达**：状态同时使用文字、色彩和必要的图标/圆点，不依赖颜色单独传达含义。
5. **同一套 UI**：浏览器与 Tauri 共用令牌、组件和响应式规则，不建立平台分叉样式。

设计令牌的代码权威文件为 [`web/src/design-system.css`](../web/src/design-system.css)。原有 [`web/src/styles.css`](../web/src/styles.css) 暂时承载现存业务布局；页面逐步组件化后只消费令牌，不再新增无语义的十六进制颜色。

## 3. 字体与数字

字体栈：`Inter, PingFang SC, Microsoft YaHei, Noto Sans CJK SC, system-ui, sans-serif`。系统不下载外部字体，保证国内内网和 Tauri 离线环境稳定。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | 38 / 1.25 | 700 | 登录欢迎、Dashboard 主问候；每页最多一个 |
| H1 | 30 / 1.25 | 700 | 业务页面标题 |
| H2 | 24 / 1.25 | 700 | Drawer 标题、主要分区 |
| H3 | 20 / 1.25 | 650 | 卡片/报表分组标题 |
| H4 | 16 / 1.55 | 650 | 小卡片、表单分组 |
| Body | 14 / 1.55 | 400 | 表格、表单、正文 |
| Assist | 13 / 1.55 | 400 | 说明、筛选结果、分页统计 |
| Caption | 12 / 1.55 | 400/650 | 时间、编号、状态标签、表头 |

规则：

- 数量、金额、百分比和序号使用 `font-variant-numeric: tabular-nums`。
- 表格数字右对齐，文本左对齐，短状态居中；不要用空格模拟数字对齐。
- 货币显示为 `¥ 1,234.56`，数量保留业务需要的小数位，不展示无意义尾零。
- 编号可使用等宽字体，但名称和中文正文不得使用等宽字体。
- 辅助文字最小 12px；交互控件文字最小 14px。

## 4. 空间、形状和层级

### 4.1 间距

采用 4px 网格：`4, 8, 12, 16, 20, 24, 32, 40, 48, 64`。

- 图标与文字：8px。
- 同组字段：12–16px。
- 卡片内边距：桌面 20–24px，手机 16px。
- 卡片间距：12–16px。
- 页面标题至首个内容块：24px。
- 大区块之间：32–40px。
- 页面左右边距：桌面 24–64px，平板 20–24px，手机 14–16px。

### 4.2 圆角

- 输入、按钮、表格内操作：8px。
- 筛选器、普通卡片：10–12px。
- Dashboard 快捷卡、空状态：16px。
- 状态标签和分段筛选：胶囊圆角。
- Dialog、Drawer 不使用超过 16px 的装饰性圆角。

### 4.3 阴影

- `xs`：边界不明显的白色筛选栏。
- `sm`：hover 卡片、下拉菜单。
- `md`：Dialog、Drawer。
- `lg`：登录卡片或重要浮层。

常驻业务卡片优先使用边框而非阴影。阴影不能替代清晰的容器边界。

### 4.4 Z 轴

| 层级 | Token/建议值 | 用途 |
| --- | --- | --- |
| 内容 | 0 | 页面与卡片 |
| Sticky | 10 | 表头、页内粘性工具条 |
| Header | 20 | 顶栏 |
| Overlay | 1000+ | 下拉、Dialog、Drawer（遵循 Element Plus） |
| Toast | 3000 | Message/Notification |

不要在业务组件内随意增加更高的 `z-index`。弹层应使用 Element Plus 的 teleport/append-to-body 机制。

## 5. 密度和布局尺寸

默认控件高度 40px，适合触屏和桌面混合使用；小号 32px 仅用于表格内次级操作和紧凑筛选；大号 48px 仅用于登录和关键提交。

表格提供两档密度：

- 标准：48px 行高，适合仓库、任务单、模具和带两行主副信息的列表。
- 紧凑：40px 行高，适合权限、审计、基础档案等纯文本高频扫描列表。

应用框架基准：顶栏 68px、侧栏 224px、内容最大宽度 1240px。详情 Drawer 标准宽度 620px，复杂任务/模具详情 720px；移动端统一为 100%。

## 6. 动效

- 快速反馈 120ms：按钮、输入边框、标签。
- 标准切换 160ms：卡片 hover、筛选器、菜单选中。
- 空间变化 240ms：Drawer、Dialog、折叠区。
- 标准缓动：`cubic-bezier(0.2, 0, 0, 1)`。

禁止对表格行、关键数字和页面主体使用循环动画。加载使用 Skeleton 或 Element Plus loading；不得让布局在加载完成时大幅跳动。系统尊重 `prefers-reduced-motion: reduce`。

## 7. Element Plus 组件规范

### 7.1 Button

| 场景 | Element Plus | 规则 |
| --- | --- | --- |
| 页面主操作 | `type="primary"` | 每个操作区最多一个，例如“新增任务单” |
| 次操作 | 默认按钮 | 刷新、取消、返回、测试连接 |
| 轻操作 | `link` / `text` | 表格查看、编辑；文字必须描述动作 |
| 正向结案 | `type="success"` | 确认完成，不等同普通保存 |
| 高风险 | `type="danger"` | 删除、冲销、强制完成；必须确认 |
| 等待请求 | `:loading="true"` | 同时禁用重复提交，原文字保留语义 |

按钮顺序从左至右为“取消/次要 → 主要/危险”；Dialog footer 中取消在左、确认在右。只有图标的按钮必须有 `aria-label` 和 tooltip。

### 7.2 Input、Select、DatePicker

- 表单使用顶部标签，不能只依赖 placeholder。
- 必填项显示必填标识；错误紧邻字段，说明如何修正。
- 搜索框允许清空，并在回车时执行搜索。
- Select 超过 8 项时启用可搜索；多选使用折叠标签并提供已选数量。
- 数量与金额使用 `el-input-number`，由 API 契约决定精度和范围。
- 只读用只读文本/描述列表；若必须保留输入外观，明确标注“只读”，不要伪装为 disabled。
- disabled 只表示当前不可操作，旁边应解释依赖条件。

### 7.3 筛选器

统一结构：关键词 → 业务状态 → 分类/部门 → 日期范围 → 重置；“新增”不放在筛选栏里。桌面端一行换行，手机端纵向排列。自动筛选应在值改变后立即执行；需组合多个条件时使用“查询”按钮，项目内同类页面保持一致。

筛选栏下方显示“共 N 条”和当前筛选摘要。无筛选结果与系统无数据使用不同空状态文案。

### 7.4 Table

- 表头 12px/700，浅灰背景；正文 14px。
- 首列优先放名称与编号，两行结构中名称为主、编号为辅。
- 操作列固定在右侧，宽度只容纳 1–3 个最高频操作，其余放“更多”。
- 金额、数量右对齐；操作、短状态可居中。
- 长文本截断并用 tooltip/Drawer 查看全文；禁止无限撑宽。
- 低库存只强调数量/状态单元格，不将整行染红。
- 使用 `row-key` 保证更新稳定；加载时保留表头或显示等高 Skeleton。
- 移动端不强行压缩全部列：保留主信息、状态、关键数值和操作，其余进入详情 Drawer。

### 7.5 Card

- 普通卡片：白底、1px 默认边框、10–12px 圆角，不使用阴影。
- Dashboard 快捷卡：16px 圆角，hover 仅轻微抬升 2px。
- 指标卡：标签、数值、解释三层；数值使用 24–30px；卡片必须能进入明细或明确不可点击。
- 同一网格中的卡片高度一致；不允许仅用大图标填充空白。

### 7.6 状态 Tag

状态 Tag 由“圆点 + 中文状态”组成，默认高度 24px。Element Plus 映射：

- `success`：正常、已完成、已归还、连接正常。
- `warning`：待确认、临近阈值、即将保养、部分完成。
- `danger`：加急、逾期、库存不足、维修异常、失败。
- `info`：草稿、暂停、只读、未知、已停用。

普通业务分类（如“产品”“生产物资”）使用 `effect="plain"`，不得伪装成状态告警。

### 7.7 Alert、Message 与 Notification

- Alert 用于页面内持续存在、需要解释或可处理的问题。
- Message 用于用户刚完成动作后的短反馈，成功 2–3 秒，错误应保留足够阅读时间。
- Notification 仅用于跨页面或后台完成事件，例如未来导出完成和任务实时提醒。
- 错误必须说明失败对象和下一步，如“库存流水加载失败，请重试”，不要只显示“请求失败”。
- 同一错误不得同时以 Alert、Message 和 Notification 三种形式重复出现。

### 7.8 Dialog

适用：确认、小型配置、少量字段表单。桌面宽 480–680px，手机最大 `calc(100vw - 28px)`。超过 8 个字段、有多个分区或需要查阅上下文时改用 Drawer/独立页面。

危险确认必须写出对象与影响。例如：

> 冲销后将生成反向库存流水，原记录仍保留。确定冲销单据 RK-20260826-001？

确认按钮使用具体动作“确认冲销”，不要使用含糊的“确定”。批量危险操作可要求用户再次核对数量，但不采用无必要的输入确认。

### 7.9 Drawer

- 简单物品详情 620px；任务和模具复杂详情 720px；手机 100%。
- 顶部固定显示编号、名称、状态和关闭按钮。
- 内容顺序：摘要 → 主要操作 → 业务详情 → 图片/记录/日志。
- 长 Drawer 的主要保存操作应在底部保持可达，滚动内容不能隐藏提交状态。
- 关闭前若有未保存修改，应二次确认。
- Drawer 关闭后销毁临时表单与敏感数据，重新打开按最新 API 数据加载。

### 7.10 Pagination

- 左侧显示“共 N 条”，右侧放分页器。
- 默认每页 20 条，可选 20/50/100；移动端只保留上一页、页码、下一页和总数。
- 改变筛选条件后回到第一页；刷新当前页时保留条件。
- 删除当前页最后一项后自动回到有效页。

## 8. 全部系统状态

每个请求型页面必须具备以下状态：

| 状态 | 展示 | 可执行动作 |
| --- | --- | --- |
| 首次加载 | 等高 Skeleton，避免空白闪烁 | 无或取消 |
| 局部刷新 | 保留旧数据并显示局部 loading | 可取消筛选，不重复提交 |
| 系统空数据 | 图标 + “尚未创建…” + 说明 | 有权限时提供主要创建操作 |
| 筛选空结果 | “没有符合当前条件的结果” | 清空筛选 |
| 网络/API 错误 | Error Alert/状态面板 + 可诊断文案 | 重试；必要时检查服务器地址 |
| 无权限 | 锁/权限图标 + 所需能力说明 | 返回首页或联系管理员 |
| 只读 | 页面标题旁“仅查看”Tag | 隐藏写操作，保留阅读能力 |
| 提交中 | 按钮 loading、字段保持可读 | 禁止重复提交 |
| 提交成功 | Message + 刷新局部数据 | 继续工作或关闭 |
| 提交失败 | 表单上方 Alert；字段错误落字段 | 修改后重试 |

空状态不能伪装成功；权限不足不能使用“暂无数据”文案。接口错误时不要清空用户已经输入的表单。

## 9. ERP 专用模式

### 9.1 库存预警

定义三档：

- 正常：`quantity > safety_stock`，成功色或普通文本。
- 临界：`quantity > 0 && quantity <= safety_stock`，警告色，文案“低于安全库存”。
- 缺货：`quantity <= 0`，危险色，文案“缺货”。

表格只强调库存数值和状态 Tag。Dashboard 指标可用危险/警告色，但不使用整卡高饱和红底。办理出库时若数量不足，在数量字段下显示当前可用库存并阻止提交；最终仍以后端校验为准。

### 9.2 任务优先级与进度

- 普通：信息/中性 Tag，文本“普通”。
- 加急：危险 Tag + 文本“加急”，列表名称前可加小型告警图标。
- 逾期：由截止时间与未完成状态计算，危险色 + “逾期 N 天”。逾期比加急具有更高排序/展示优先级。
- 部门进度必须显示百分比数值，Progress 不能单独表达完成程度。
- 状态主序列：草稿 → 已派发/处理中 → 待确认 → 已完成；暂停是分支状态，强制完成在日志中永久可辨识。

任务操作只展示当前状态允许的动作。强制完成使用危险确认；正常完成使用成功确认，二者不可共用模糊文案。

### 9.3 模具状态与保养

- 正常/在库：成功。
- 借出：信息；同时显示借用部门与预计归还信息（若有）。
- 维修：警告；维修逾期后升级危险。
- 停用/报废：信息或危险，必须用明确文本区分。
- 距保养日期 7 天内：警告“即将保养”。
- 已过保养日期：危险“保养逾期”。

模具详情顶部始终显示当前位置。借出、归还、维修、完成维修、登记保养作为互斥状态动作，不同时展示不合法操作。

### 9.4 成本字段权限

`cost:view` 是数据安全边界，不只是视觉开关：

- 无权限时不渲染成本、单价、金额列和表单字段，不能仅用 CSS 隐藏。
- 无权限接口响应也不得包含对应值；前端不得尝试推算。
- 报表分组若依赖金额，应整体替换为数量视图，并显示“金额已按权限隐藏”。
- 导出功能沿用相同权限，不得让下载文件绕过页面权限。
- 不使用 `***` 占位敏感金额，因为这会泄露字段存在和产生误解。

### 9.5 危险操作

删除、冲销、强制完成、停用、报废和覆盖式替换必须：

1. 由明确的用户点击触发，不在批量选择后自动执行。
2. 二次确认中显示对象名称/编号和不可逆或后续影响。
3. 确认按钮使用危险色与具体动作。
4. 请求中锁定按钮并使用幂等/后端保护（以 API 契约为准）。
5. 成功后刷新受影响数据并记录审计；失败时保留上下文。

## 10. 页面模板

### 10.1 登录

- 全屏浅蓝灰背景，品牌色仅作局部柔和光晕。
- 420px 登录卡居中，logo、标题、账号、密码、主登录按钮、错误 Alert 顺序固定。
- Tauri 服务器设置置于分隔线后，默认折叠或弱化，不抢占登录主任务。
- 初始焦点在账号；密码支持显示/隐藏；Enter 提交；错误后焦点回到可修正字段。

### 10.2 Dashboard

- 顶部：问候、角色/部门、服务状态、客户端更新提示。
- 第一屏：4–6 个与当前账号相关的指标/待办，不为无权限数据保留空卡。
- 第二层：常用功能快捷入口，按角色排序。
- 第三层：待处理任务、低库存、待保养模具和最近动态。
- 管理员偏向异常与系统状态，办公室偏向任务确认与业务统计，部门终端偏向本部门任务。

### 10.3 通用列表

结构：面包屑/标题/说明/新增 → 业务分段 → 筛选栏 → 结果摘要 → 表格 → 分页。加载、空、错、无权限状态在表格区域稳定替换，避免页面跳动。

客户、联系人、供应商、用户、部门、终端、角色、权限和审计均使用此模板，根据数据量选择标准或紧凑密度。

### 10.4 详情 Drawer

结构：固定标题区 → 3–4 个摘要数据 → 合法主要操作 → 分区详情 → 图片 → 履历/日志。业务办理表单在当前对象上下文中展开，不让用户再次选择已经确定的对象或默认仓库。

### 10.5 报表

- 顶部筛选包含日期范围、部门和业务类型；筛选条件决定所有图表与明细。
- 指标卡 → 关键趋势/分布 → 异常明细，先结论后细节。
- 图表必须有标题、单位、图例和无数据状态；颜色遵循语义或固定序列。
- 每个汇总应提供明细入口；导出按钮展示准备中、成功、失败状态。
- 成本权限在指标、图表、tooltip、明细和导出中一致生效。

### 10.6 系统设置

- 用户/角色/权限关系使用主列表 + 配置 Dialog/Drawer，不使用难以扫描的巨大权限矩阵。
- 权限按业务域分组，并明确“查看/写入/敏感数据”层级。
- 审计记录只读，突出操作人、时间、对象、动作和结果。
- 版本与更新按“更新源状态 → 服务端包 → 客户端包”组织，普通查看用户不显示立即检查操作。

## 11. 响应式策略

| 范围 | 定义 | 主要行为 |
| --- | --- | --- |
| `>= 1280px` | 宽桌面 | 224px 侧栏，内容最大 1240px，4–6 列指标 |
| `1024–1279px` | 桌面/大平板 | 保留侧栏或紧凑侧栏，指标 3–4 列 |
| `768–1023px` | 平板 | 侧栏转抽屉，双列卡片，筛选允许换行 |
| `< 768px` | 手机 | 单列内容，16px 边距，Drawer 100%，筛选纵排 |

手机端规则：

- 顶部栏只保留 logo/名称、状态入口、用户菜单；不使用横向滚动模块按钮作为长期导航，后续改为抽屉导航。
- 表格展示最小列集，点击整行或“详情”进入 Drawer；确需横向滚动的审计/权限表应给出滚动提示。
- 主要按钮宽度可占满；按钮点击区域至少 44×44px。
- Dialog 留 14px 屏幕边距；软键盘弹出时表单字段和提交按钮仍可滚动到。
- 图表改为纵向排列，tooltip 也必须支持触摸。

## 12. 可访问性

- 正文和关键数据达到 WCAG AA 对比度目标；`#079ed1` 不承载白色小字号正文，实心交互面使用 `#0758ad`。
- 所有交互可用键盘完成，焦点环清楚且不被全局 `outline: none` 移除。
- 输入必须有可关联 label，错误信息使用 `aria-describedby`，必填使用语义属性。
- 图标按钮提供可访问名称；业务图片提供有意义的 alt，纯装饰图片使用空 alt。
- 状态不只靠颜色，图表必须提供文字摘要或明细表。
- Toast 不能是关键错误的唯一载体；高风险确认应被屏幕阅读器正确读出标题与影响。
- 尊重减少动态偏好；不自动播放闪烁、滚动或大幅位移动画。

## 13. Element Plus 映射

主题桥接已在 `design-system.css` 中覆盖以下变量族：

- `--el-color-primary/success/warning/danger/info`
- `--el-text-color-*`
- `--el-bg-color-*` 与 `--el-fill-color-*`
- `--el-border-color-*`
- `--el-border-radius-*`
- `--el-box-shadow-*`
- `--el-component-size-*`
- `--el-disabled-*`
- `--el-transition-duration*`

组件映射建议：

| 设计模式 | Element Plus |
| --- | --- |
| 应用导航 | `el-menu`, `el-menu-item`, `el-drawer`（移动） |
| 快捷/指标卡 | `el-card` |
| 筛选与表单 | `el-form`, `el-input`, `el-select`, `el-date-picker`, `el-input-number` |

## 14. 维护规则

所有新模块和页面必须执行以下规则：

1. 从 `design-system.css` 使用语义 Token；禁止在 Vue scoped CSS 中新增品牌/状态十六进制颜色。
2. 状态映射集中维护，同一后端状态在列表、详情、报表中使用相同文字与 tone。
3. 页面交付同时覆盖 loading、空数据、筛选空结果、错误、无权限、只读和成功反馈。
4. 写操作严格依据已确认 API 契约和权限；不可用操作隐藏，依赖不足时给出说明。
5. `cost:view` 相关元素用 Vue 条件渲染，不使用 CSS 隐藏。
6. 优先复用 Element Plus 与现有请求封装，不增加新 UI 框架、图标体系或状态库。
7. 响应式至少在 1440、1024、768 和 375px 四个宽度验证；Web 与 Tauri 都运行构建。
8. 键盘检查覆盖 Tab 顺序、focus-visible、Dialog/Drawer 焦点和 Escape 行为。
9. 危险操作必须验收确认文案、loading 防重复、成功刷新和失败保留上下文。
10. 页面改造完成后更新本文件的“实施进度”，并由独立 UI 审查确认视觉一致性。

代码审查搜索建议：

```bash
rg -n '#[0-9a-fA-F]{3,8}|rgb\(|hsl\(' web/src --glob '*.vue' --glob '*.css'
rg -n 'cost|amount|unit_cost|avg_cost' web/src
cd web && npm run build
cd ../client && npm run build
```

第一条搜索用于发现新硬编码，不要求一次性清除旧 `styles.css`；改造到的区域必须收敛到令牌。
