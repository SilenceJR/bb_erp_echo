# 博邦 ERP UI 设计系统

版本：3.0（Astra 全产品翻新）
设计方向：精密工作台：中性灰白、克制层级、均衡密度、真实业务内容
适用范围：Vue 3 + Element Plus Web，以及复用相同入口的 Tauri 桌面端

## 1. 设计目标

博邦 ERP 是工厂内网中高频使用的数据工具。视觉设计的首要目标不是“展示感”，而是让办公室、仓库、生产部门和管理员在长时间操作中快速定位信息、减少误操作并清楚判断当前状态。

当前方案遵循五项原则：

1. **任务优先**：页面标题、待办、筛选、主要操作和异常数据形成稳定层级。
2. **清楚胜过装饰**：保留品牌识别，不使用大面积渐变、玻璃拟态、装饰插画或无业务意义的图表。
3. **密度可控**：默认使用 40px 控件和 48px 表格行；超长档案列表可切换为 32px 控件和 40px 紧凑行。
4. **状态有冗余表达**：状态同时使用文字、色彩和必要的图标/圆点，不依赖颜色单独传达含义。
5. **同一套 UI**：浏览器与 Tauri 共用令牌、组件和响应式规则，不建立平台分叉样式。

本版本是从启动页、连接、登录到主工作区及全部模块的整体翻新。旧前端结构不构成兼容约束；但页面不得以静态导航、入口数量、账号类型、空图表或假零值填充空间。首页只保留真实业务入口，统计只呈现来源可用且具有判断价值的结果；不可用、无记录、无权限和加载失败分别表达。

设计令牌的代码权威文件为 [`web/src/design-system.css`](../web/src/design-system.css)。原有 [`web/src/styles.css`](../web/src/styles.css) 暂时承载现存业务布局；页面逐步组件化后只消费令牌，不再新增无语义的十六进制颜色。

## 1.1 客户端信息架构

工作区采用“左侧业务导航 / 中央业务内容 / 右侧对象详情”的三栏结构。中央区域继续承载现有 ERP 页面；左右栏只承担导航和上下文，不复制业务页面。

- 左栏有 `full`（224px）、`icon`（64px）、`hidden`（0px）三档，选择仅保存在本机。图标模式必须保留 Tooltip、当前项和无障碍名称；隐藏后必须保留恢复入口。
- 所有现有详情、新增、编辑、设置和权限配置入口固定使用单一右侧停靠轨道：普通详情 420px，标准表单和信息密集内容 520px。右轨优先保证中央工作区至少 720px；空间不足时临时收起持久导航，并提供覆盖式业务导航入口，不把右轨改成模态 Drawer。
- 右侧停靠轨道与中央内容共享同一网格：打开时中央区与右轨在 180ms 内同步调整，正文最多 6px 轻位移。新的业务表面直接替换当前内容，不保留历史面板栈；连续进入后关闭一次即清空右轨。关闭必须先经过提交中和未保存守卫，不绑定中央内容的任意点击。
- 服务器连接成功属于低频状态，只在“设置 / 连接与服务”中展示；检测中使用轻量反馈，失败时才进入全局高优先级提示。
- 任务单、仓库、供应商和统计报表本阶段保留现有页面结构；未初始化的数据模块展示明确过渡状态，不把不可用数据渲染成真实零值。

## 1.2 外观偏好

外观设置仅保存在当前设备，不随账号同步：

- `data-theme="light|dark"`，本地键 `bb_erp_theme_mode`；默认 `light`。
- `data-accent="bobbang|teal|violet"`，本地键 `bb_erp_theme_accent`；默认 `bobbang`。
- 主题必须在 Vue 挂载前应用，避免启动闪白；Element Plus Teleport 浮层必须继承相同的主题属性。
- 品牌色仅改变主操作、焦点和选中状态。成功、警告、危险、库存异常等业务语义色保持固定含义。
- 暗色使用深灰多层表面，不使用大面积纯黑；表格、弹层、输入框和边界仍须清楚可辨。

## 1.3 设计工具与本地素材结论

- Figma 本轮只允许写入免费个人 Draft。实际账号仅发现 Starter 团队查看权限，未满足“创建、修改、回读、截图和链接”完整门槛，因此没有写入任何 Figma 团队文件，也未把不可回读的稿件作为实现依据。
- Eagle 已只读检查字体、24px SVG 图标和 ERP/SaaS 参考。现有字体包含 MiSans、HarmonyOS Sans SC、OPPO Sans、阿里巴巴普惠体和思源系列，但完整字重体积较大，本轮不额外打包，继续使用稳定系统字体栈。
- Eagle 中 neuicons 数量充足，但样例线条粗细和语义风格不完全统一；现有 ERP 参考也偏旧或偏营销展示，因此不整套搬用。项目继续使用 Element Plus 图标和统一令牌，待有明确匹配的单项素材再按需引入。
- 按内部工厂使用约定，本轮不执行 Eagle 素材商业授权检查；素材是否采用只依据视觉一致性、技术格式、中文可读性和客户端稳定性。

## 3. 字体与数字

字体栈：`Microsoft YaHei UI, PingFang SC, system-ui, -apple-system, sans-serif`。系统不下载外部字体，保证 Windows、WebView2、浏览器和 Tauri 离线环境稳定；数字统一启用等宽数字特性。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | 38 / 1.25 | 700 | 登录欢迎、Dashboard 主问候；每页最多一个 |
| H1 | 30 / 1.25 | 700 | 业务页面标题 |
| H2 | 24 / 1.25 | 700 | Drawer 标题、主要分区 |
| H3 | 20 / 1.25 | 650 | 卡片/报表分组标题 |
| H4 | 16 / 1.55 | 650 | 小卡片、表单分组 |
| Body | 14 / 1.55 | 400 | 表格、表单、正文 |
| Assist | 13 / 1.55 | 400 | 说明、筛选结果、分页统计 |
| Caption | 12 / 1.55 | 400/650 | 时间、编号、状态标签、表头 |

规则：

- 数量、金额、百分比和序号使用 `font-variant-numeric: tabular-nums`。
- 表格数字右对齐，文本左对齐，短状态居中；不要用空格模拟数字对齐。
- 货币显示为 `¥ 1,234.56`，数量保留业务需要的小数位，不展示无意义尾零。
- 编号可使用等宽字体，但名称和中文正文不得使用等宽字体。
- 辅助文字最小 12px；交互控件文字最小 14px。

## 4. 空间、形状和层级

### 4.1 间距

采用 4px 网格：`4, 8, 12, 16, 20, 24, 32, 40, 48, 64`。

- 图标与文字：8px。
- 同组字段：12–16px。
- 卡片内边距：桌面 20–24px。
- 卡片间距：12–16px。
- 页面标题至首个内容块：24px。
- 大区块之间：32–40px。
- 页面左右边距：桌面 24–64px；1024px 窗口使用 20–24px。

### 4.2 圆角

- 输入、按钮、表格内操作：6px。
- 表格与普通内容容器：8px。
- 详情面板和普通卡片：10px。
- 低频浮层与登录容器：12px。
- 状态标签和分段筛选：胶囊圆角。
- Dialog、Drawer 不使用超过 16px 的装饰性圆角。

### 4.3 阴影

- `xs`：边界不明显的白色筛选栏。
- `sm`：hover 卡片、下拉菜单。
- `md`：Dialog、Drawer。
- `lg`：登录卡片或重要浮层。

常驻业务卡片优先使用边框而非阴影。阴影不能替代清晰的容器边界。

### 4.4 Z 轴

| 层级 | Token/建议值 | 用途 |
| --- | --- | --- |
| 内容 | 0 | 页面与卡片 |
| Sticky | 10 | 表头、页内粘性工具条 |
| Header | 20 | 顶栏 |
| Overlay | 1000+ | 下拉、Dialog、Drawer（遵循 Element Plus） |
| Toast | 3000 | Message/Notification |

不要在业务组件内随意增加更高的 `z-index`。弹层应使用 Element Plus 的 teleport/append-to-body 机制。

## 5. 密度和布局尺寸

默认控件高度 40px，适合触屏和桌面混合使用；小号 32px 仅用于表格内次级操作和紧凑筛选；大号 48px 仅用于登录和关键提交。

表格提供两档密度：

- 标准：48px 行高，适合仓库、任务单、模具和带两行主副信息的列表。
- 紧凑：40px 行高，适合权限、审计、基础档案等纯文本高频扫描列表。

应用框架基准：顶栏 56px、侧栏完整态 224px、图标态 64px、隐藏态 0px，内容最大宽度 1240px。停靠详情标准宽度 420px，标准表单、设置、权限和图片密集内容 520px；当侧栏 + 中央区 + 右轨不能同时满足中央 720px 时，持久导航临时转为覆盖式导航。Windows 窗口最小为 1024×680，主要验收分辨率为 1920×1080。

## 6. 动效

- CSS Transition 是默认方案：按钮、输入边框、标签、普通菜单、表格行 hover、颜色、边框和阴影使用 120–160ms 的令牌过渡。
- Motion 只用于状态驱动或需要空间连续性的交互：启动/工作台阶段、页面切换、Layout、列表变化、Shared element 和 Toast stack。Element Plus Teleport 型 Dialog/Drawer 的正文不得使用 `motion-v` 的初始透明度或嵌套 `AnimatePresence` 控制可见性；弹层开闭、焦点和正文可读性由 Element Plus 保证。
- Spring/Timeline 只用于低频高价值反馈；当前 ERP 不用于普通表格扫描、持续循环动画或每次点击的弹跳效果。
- 标准缓动：`cubic-bezier(0.2, 0, 0, 1)`；页面/阶段切换最多 240ms，不能阻塞业务操作。
- `motion-v` 统一通过 `MotionConfig` 尊重用户的 `prefers-reduced-motion`；减弱模式移除位移、缩放和布局动画，保留必要的透明度、颜色和焦点反馈。
- 当前实现：工作台首页/业务页使用轻量页面切换；单一右侧停靠轨道通过网格与面板位移形成空间连续性，首帧透明度不低于 `.92`。保留的 Drawer 回退代码没有现有业务入口；客户导入/导出等必要 Dialog 使用稳定正文容器，避免 Teleport 首帧隐藏。
- 禁止对关键数字和页面主体使用循环动画。加载使用 Skeleton 或 Element Plus loading，不得让布局在加载完成时大幅跳动。

## 7. Element Plus 组件规范

### 7.1 Button

| 场景 | Element Plus | 规则 |
| --- | --- | --- |
| 页面主操作 | `type="primary"` | 每个操作区最多一个，例如“新增任务单” |
| 次操作 | 默认按钮 | 刷新、取消、返回、重新发现 |
| 轻操作 | `link` / `text` | 表格查看、编辑；文字必须描述动作 |
| 正向结案 | `type="success"` | 确认完成，不等同普通保存 |
| 高风险 | `type="danger"` | 删除、冲销、强制完成；必须确认 |
| 等待请求 | `:loading="true"` | 同时禁用重复提交，原文字保留语义 |

按钮顺序从左至右为“取消/次要 → 主要/危险”；Dialog footer 中取消在左、确认在右。只有图标的按钮必须有 `aria-label` 和 tooltip。

### 7.2 Input、Select、DatePicker

- 表单使用顶部标签，不能只依赖 placeholder。
- 必填项显示必填标识；错误紧邻字段，说明如何修正。
- 搜索框允许清空，并在回车时执行搜索。
- Select 超过 8 项时启用可搜索；多选使用折叠标签并提供已选数量。
- 数量与金额使用 `el-input-number`，由 API 契约决定精度和范围。
- 只读用只读文本/描述列表；若必须保留输入外观，明确标注“只读”，不要伪装为 disabled。
- disabled 只表示当前不可操作，旁边应解释依赖条件。

### 7.3 筛选器

统一结构：关键词 → 业务状态 → 分类/部门 → 日期范围 → 重置；“新增”不放在筛选栏里。桌面端允许在窄窗口换行。自动筛选应在值改变后立即执行；需组合多个条件时使用“查询”按钮，项目内同类页面保持一致。

筛选栏下方显示“共 N 条”和当前筛选摘要。无筛选结果与系统无数据使用不同空状态文案。

### 7.4 Table

- 表头 12px/700，浅灰背景；正文 14px。
- 首列优先放名称与编号，两行结构中名称为主、编号为辅。
- 操作列固定在右侧，宽度只容纳 1–3 个最高频操作，其余放“更多”。
- 金额、数量右对齐；操作、短状态可居中。
- 长文本截断并用 tooltip/Drawer 查看全文；禁止无限撑宽。
- 低库存只强调数量/状态单元格，不将整行染红。
- 使用 `row-key` 保证更新稳定；加载时保留表头或显示等高 Skeleton。
- 1024px 窄窗口不强行压缩全部列：保留主信息、状态、关键数值和操作，其余进入详情 Drawer。

### 7.5 Card

- 普通卡片：白底、1px 默认边框、10–12px 圆角，不使用阴影。
- Dashboard 快捷卡：10–12px 圆角，hover 只改变边界或底色，不做悬浮抬升。
- 指标卡：标签、数值、解释三层；数值使用 24–30px；卡片必须能进入明细或明确不可点击。
- 同一网格中的卡片高度一致；不允许仅用大图标填充空白。

### 7.6 状态 Tag

状态 Tag 由“圆点 + 中文状态”组成，默认高度 24px。Element Plus 映射：

- `success`：正常、已完成、已归还、连接正常。
- `warning`：待确认、临近阈值、即将保养、部分完成。
- `danger`：加急、逾期、库存不足、维修异常、失败。
- `info`：草稿、暂停、只读、未知、已停用。

普通业务分类（如“产品”“生产物资”）使用 `effect="plain"`，不得伪装成状态告警。

### 7.7 Alert、Message 与 Notification

- Alert 用于页面内持续存在、需要解释或可处理的问题。
- Message 用于用户刚完成动作后的短反馈，成功 2–3 秒，错误应保留足够阅读时间。
- Notification 仅用于跨页面或后台完成事件，例如未来导出完成和任务实时提醒。
- 错误必须说明失败对象和下一步，如“库存流水加载失败，请重试”，不要只显示“请求失败”。
- 同一错误不得同时以 Alert、Message 和 Notification 三种形式重复出现。

### 7.8 Dialog

适用：确认、小型配置、少量字段表单。桌面宽 480–680px，并不得超过当前窗口。超过 8 个字段、有多个分区或需要查阅上下文时改用 Drawer/独立页面。客户资料导入为 760px 特例，导出预览为 1120px 特例，以容纳九列表格且仅正文滚动。

危险确认必须写出对象与影响。例如：

> 冲销后将生成反向库存流水，原记录仍保留。确定冲销单据 RK-20260826-001？

确认按钮使用具体动作“确认冲销”，不要使用含糊的“确定”。批量危险操作可要求用户再次核对数量，但不采用无必要的输入确认。

### 7.9 单一右侧停靠面板

- 所有现有详情、新增、编辑、设置和权限配置均进入同一右侧停靠轨道，不按窗口宽度切换为全屏模态 Drawer。
- 普通详情使用 420px；标准表单、设置、权限和图片密集内容使用 520px。空间不足时优先临时收起持久导航，中央区仍需尽量保留 720px。
- 新入口直接替换右轨当前内容；同一业务中的临时建档使用载体内步骤切换，“保存并选择”后回到原业务上下文，不创建第二个 Carrier。
- 顶部固定显示编号、名称、状态和关闭按钮。
- 内容顺序：摘要 → 主要操作 → 业务详情 → 图片/记录/日志。
- 长面板的主要保存操作固定在底部，只有正文滚动，不能隐藏提交状态。
- 关闭前若有未保存修改，应二次确认。
- 面板关闭后销毁临时表单与敏感数据，重新打开按最新 API 数据加载。Drawer 代码仅作为未启用回退保留。

### 7.10 Pagination

- 左侧显示“共 N 条”，右侧放分页器。
- 默认每页 20 条，可选 20/50/100。
- 改变筛选条件后回到第一页；刷新当前页时保留条件。
- 删除当前页最后一项后自动回到有效页。

## 8. 全部系统状态

每个请求型页面必须具备以下状态：

| 状态 | 展示 | 可执行动作 |
| --- | --- | --- |
| 首次加载 | 等高 Skeleton，避免空白闪烁 | 无或取消 |
| 局部刷新 | 保留旧数据并显示局部 loading | 可取消筛选，不重复提交 |
| 系统空数据 | 图标 + “尚未创建…” + 说明 | 有权限时提供主要创建操作 |
| 筛选空结果 | “没有符合当前条件的结果” | 清空筛选 |
| 网络/API 错误 | Error Alert/状态面板 + 可诊断文案 | 重试；必要时检查服务器地址 |
| 无权限 | 锁/权限图标 + 所需能力说明 | 返回首页或联系管理员 |
| 只读 | 页面标题旁“仅查看”Tag | 隐藏写操作，保留阅读能力 |
| 提交中 | 按钮 loading、字段保持可读 | 禁止重复提交 |
| 提交成功 | Message + 刷新局部数据 | 继续工作或关闭 |
| 提交失败 | 表单上方 Alert；字段错误落字段 | 修改后重试 |

空状态不能伪装成功；权限不足不能使用“暂无数据”文案。接口错误时不要清空用户已经输入的表单。

## 9. ERP 专用模式

### 9.1 库存预警

定义三档：

- 正常：`quantity > safety_stock`，成功色或普通文本。
- 临界：`quantity > 0 && quantity <= safety_stock`，警告色，文案“低于安全库存”。
- 缺货：`quantity <= 0`，危险色，文案“缺货”。

表格只强调库存数值和状态 Tag。Dashboard 指标可用危险/警告色，但不使用整卡高饱和红底。办理出库时若数量不足，在数量字段下显示当前可用库存并阻止提交；最终仍以后端校验为准。

### 9.2 任务优先级与进度

- 普通：信息/中性 Tag，文本“普通”。
- 加急：危险 Tag + 文本“加急”，列表名称前可加小型告警图标。
- 逾期：由截止时间与未完成状态计算，危险色 + “逾期 N 天”。逾期比加急具有更高排序/展示优先级。
- 部门进度必须显示百分比数值，Progress 不能单独表达完成程度。
- 状态主序列：草稿 → 已派发/处理中 → 待确认 → 已完成；暂停是分支状态，强制完成在日志中永久可辨识。

任务操作只展示当前状态允许的动作。强制完成使用危险确认；正常完成使用成功确认，二者不可共用模糊文案。

### 9.3 模具状态与保养

- 正常/在库：成功。
- 借出：信息；同时显示借用部门与预计归还信息（若有）。
- 维修：警告；维修逾期后升级危险。
- 停用/报废：信息或危险，必须用明确文本区分。
- 距保养日期 7 天内：警告“即将保养”。
- 已过保养日期：危险“保养逾期”。

模具详情顶部始终显示当前位置。借出、归还、维修、完成维修、登记保养作为互斥状态动作，不同时展示不合法操作。

### 9.4 成本字段权限

`cost:view` 是数据安全边界，不只是视觉开关：

- 无权限时不渲染成本、单价、金额列和表单字段，不能仅用 CSS 隐藏。
- 无权限接口响应也不得包含对应值；前端不得尝试推算。
- 报表分组若依赖金额，应整体替换为数量视图，并显示“金额已按权限隐藏”。
- 导出功能沿用相同权限，不得让下载文件绕过页面权限。
- 不使用 `***` 占位敏感金额，因为这会泄露字段存在和产生误解。

### 9.5 危险操作

删除、冲销、强制完成、停用、报废和覆盖式替换必须：

1. 由明确的用户点击触发，不在批量选择后自动执行。
2. 二次确认中显示对象名称/编号和不可逆或后续影响。
3. 确认按钮使用危险色与具体动作。
4. 请求中锁定按钮并使用幂等/后端保护（以 API 契约为准）。
5. 成功后刷新受影响数据并记录审计；失败时保留上下文。

## 10. 页面模板

### 10.0 推荐导航

- 一级入口固定为“首页”；业务按“业务办理 → 基础资料 → 数据与报表”组织，系统能力单独收进“系统设置”。
- “业务办理”承载任务单、仓库、模具；“基础资料”承载客户资料、供应商；“数据与报表”承载统计报表。分组只改变查找路径，不改变权限和模块 key。
- 导航顺序由模块注册表和当前账号权限决定；移动 Web 复用同一分组，仅将侧栏改为可打开式菜单，不维护第二套导航。

### 10.1 登录

- 全屏浅蓝灰背景，品牌色仅作局部柔和光晕。
- 桌面采用品牌欢迎区 + 账号登录区的双栏结构；logo、标题、账号、密码、主登录按钮、错误 Alert 顺序固定。
- Tauri 在启动页自动发现并验证局域网服务；零结果或发现失败才提供手动地址，验证成功后再进入登录。Web 只验证当前站点服务。
- 初始焦点在账号；密码支持显示/隐藏；Enter 提交；错误后焦点回到可修正字段。

### 10.2 Dashboard

- 顶部：问候、角色/部门、服务状态、客户端更新提示。
- 第一屏只显示服务端真实返回、当前账号可处理的任务或异常；没有可靠聚合数据时自然留白，不制造“今日关注”或占位指标。
- 只展示来源可核对且能辅助判断的业务摘要，不以“入口数量”“可用业务数量”等非业务数字填充页面。
- 常用功能按角色与频率排序，完整业务入口由左侧导航承担，不在首页重复铺满。
- 管理员偏向异常与系统状态，办公室偏向任务确认与业务统计，部门终端偏向本部门任务。

### 10.3 通用列表

结构：面包屑/标题/说明/新增 → 业务分段 → 筛选栏 → 结果摘要 → 表格 → 分页。加载、空、错、无权限状态在表格区域稳定替换，避免页面跳动。

客户、联系人、供应商、用户、部门、终端、角色、权限和审计均使用此模板，根据数据量选择标准或紧凑密度。

### 10.4 详情 Drawer

结构：固定标题区 → 3–4 个摘要数据 → 合法主要操作 → 分区详情 → 图片 → 履历/日志。业务办理表单在当前对象上下文中展开，不让用户再次选择已经确定的对象或默认仓库。

### 10.5 报表

- 顶部筛选包含日期范围、部门和业务类型；筛选条件决定所有图表与明细。
- 指标卡 → 关键趋势/分布 → 异常明细，先结论后细节。
- 图表必须有标题、单位、图例和无数据状态；颜色遵循语义或固定序列。
- 每个汇总应提供明细入口；导出按钮展示准备中、成功、失败状态。
- 成本权限在指标、图表、tooltip、明细和导出中一致生效。

### 10.6 系统设置

- 用户/角色/权限关系使用主列表 + 单一右侧配置面板，不使用难以扫描的巨大权限矩阵。
- 权限按业务域分组，并明确“查看/写入/敏感数据”层级。
- 审计记录只读，突出操作人、时间、对象、动作和结果。
- 版本与更新按“更新源状态 → 服务端包 → 客户端包”组织，普通查看用户不显示立即检查操作。

## 11. Windows 桌面适配策略

| 范围 | 定义 | 主要行为 |
| --- | --- | --- |
| `>= 1600px` | 1080P 主窗口 | 224px 侧栏，内容最大 1240px，4–6 列指标 |
| `1280–1599px` | 普通桌面窗口 | 筛选允许换行；右轨打开后若中央不足 720px，持久导航临时转为覆盖式导航 |
| `1024–1279px` | 最小桌面窗口 | 右轨打开时优先保留中央工作区，业务导航按需覆盖打开；表格可横向滚动 |

## 12. 可访问性

- 正文和关键数据达到 WCAG AA 对比度目标；`#079ed1` 不承载白色小字号正文，实心交互面使用 `#0758ad`。
- 所有交互可用键盘完成，焦点环清楚且不被全局 `outline: none` 移除。
- 输入必须有可关联 label，错误信息使用 `aria-describedby`，必填使用语义属性。
- 图标按钮提供可访问名称；业务图片提供有意义的 alt，纯装饰图片使用空 alt。
- 状态不只靠颜色，图表必须提供文字摘要或明细表。
- Toast 不能是关键错误的唯一载体；高风险确认应被屏幕阅读器正确读出标题与影响。
- 尊重减少动态偏好；不自动播放闪烁、滚动或大幅位移动画。

## 14. 维护规则

所有新模块和页面必须执行以下规则：

1. 从 `design-system.css` 使用语义 Token；禁止在 Vue scoped CSS 中新增品牌/状态十六进制颜色。
2. 状态映射集中维护，同一后端状态在列表、详情、报表中使用相同文字与 tone。
3. 页面交付同时覆盖 loading、空数据、筛选空结果、错误、无权限、只读和成功反馈。
4. 写操作严格依据已确认 API 契约和权限；不可用操作隐藏，依赖不足时给出说明。
5. `cost:view` 相关元素用 Vue 条件渲染，不使用 CSS 隐藏。
6. 优先复用 Element Plus 与现有请求封装，不增加新 UI 框架、图标体系或状态库。
7. 窗口至少在 1920×1080、1440×900 和最小 1024×680 验证；Web 与 Tauri 都运行构建。
8. 键盘检查覆盖 Tab 顺序、focus-visible、Dialog/Drawer 焦点和 Escape 行为。
9. 危险操作必须验收确认文案、loading 防重复、成功刷新和失败保留上下文。
10. 页面改造完成后更新本文件的“实施进度”；先由独立 `ui_reviewer` 检查完整窗口比例、响应式、主题、焦点、动效与可访问性，P0/P1 修复复验后，再由项目负责人进行最终成品验收。
11. 列表优先展示高频识别字段和高频动作；同码新增、默认切换、删除等低频操作收进详情，不为展示数据模型而堆叠“资料数”“默认状态”等低价值列。
12. 统计区域必须服务当前决策。少量目录计数使用单行摘要，不使用四张大卡重复占据首屏；只有需要比较、预警或趋势判断的指标才使用 `MetricCard`。
13. 对已确认规模不超过约 1000 条的主数据，可按后端允许的分页大小分批取得完整快照，再在内存中即时搜索、筛选和分页；输入和翻页不得触发重复列表请求。
14. 后台刷新必须保留旧数据，完整新快照成功后再原子替换；失败时保留列表并原位提示，禁止在有缓存时切换为整页骨架、空态或错误页造成页面抖动。
15. 桌面应用壳层应固定顶部栏和左侧导航，只让主内容区独立滚动；页面实现和项目负责人验收都必须检查页面滚动后的导航可达性。

### 14.1 高频优先与稳定列表审查

以下问题在设计稿、实现和项目负责人 UI 验收中均作为通用检查项：

- 当前列或按钮是否帮助用户完成高频识别或动作；若只是在重复后端字段，应删除或移入详情。
- 统计块是否提供新的业务判断；只有目录总数时应压缩为轻量摘要。
- 搜索是否需要额外点击；小规模主数据应优先输入即过滤，并保留前端分页以控制阅读密度。
- 加载、刷新、筛选和翻页是否改变列表高度、列宽或整页状态；有旧数据时不得清空再加载。
- 桌面侧栏、顶部栏和当前操作入口是否在长列表滚动后仍可到达。

代码审查搜索建议：

```bash
rg -n '#[0-9a-fA-F]{3,8}|rgb\(|hsl\(' web/src --glob '*.vue' --glob '*.css'
rg -n 'cost|amount|unit_cost|avg_cost' web/src
cd web && npm run build
cd ../client && npm run build
```

第一条搜索用于发现新硬编码，不要求一次性清除旧 `styles.css`；改造到的区域必须收敛到令牌。

## 17. 推荐改造顺序

1. 提取 `AppShell` 与固定桌面侧栏，统一页面导航入口。
2. 提取 `PageHeader`、`FilterBar`、`PageState`、`StatusTag`、`DataTableShell`。
3. 用通用列表模板改造客户/供应商，验证基础组件覆盖能力。
4. 改造仓库列表与物品详情，验证库存预警、权限和复杂表单。
5. 改造任务单与模具，补齐进度、图片资料和批量操作模式。
6. 改造 Dashboard 和统计报表，使异常与待办成为首页重点。
7. 最后统一系统设置、版本更新、登录及全站响应式细节。

每完成一批页面，都应运行 Web 与 Tauri 构建，并在 1920×1080、1440×900、1024×680 窗口审查后更新实施进度。

第一批（2026-08-26）只改造应用框架和客户/供应商验证页面。仓库、任务单、模具、统计、更新中心仍沿用现有业务模板，后续应按上述顺序逐批迁移，不能将第一批视为全站改造完成。

第二批初始阶段（2026-08-26）完成仓库与任务单的 P0 交互：出入库表单显示当前/预计库存与提交摘要，并处理重复提交和未保存关闭确认。客户端优先整改后统一为桌面列表和固定导航结构。

第二批扩展（2026-08-26）落地 `MetricCard`，将 Dashboard 调整为“工作概览 → 今日关注 → 常用功能 → 全部业务”的清晰层级；仓库、任务和模具增加当前页语义指标，其中“当前页”不得误写成全量数据。统计报表增加显式加载、保留旧数据时的错误 Alert、各分区空状态和按日期合并排序的相对趋势条，并继续遵守成本字段权限隐藏。模具新台账不承载旧生命周期动作；首页真实待办计数仍需先建立经确认的聚合 API 契约。

静态复验修正：物品右侧停靠面板的关闭、Esc、模块切换和退出登录共用同一关闭守卫；库存提交期间拒绝关闭，已填写表单必须明确确认放弃，守卫通过后才执行实际关闭。任务列表和详情同时展示总体进度百分比与已完成部门数，未分配部门时明确显示 `0%`。

第二批独立审查修正：仓库详情、模具详情和任务日志分别维护 loading/error/data 状态，失败状态必须提供原位重试；依赖详情的写操作在成功取得数据前不可执行，详情未返回库存数量时使用“—”而不是伪装成真实 0。任务交期使用统一 `workorderDueState`，完成或取消任务不再标记逾期，其余任务在桌面列表和 Drawer 统一显示“逾期 N 天”。Dashboard 健康检查采用 checking/healthy/error 三态；无实时聚合数据的“今日关注”入口只使用 info，不以 warning/success 暗示实时异常。

模具页面只维护新台账字段、固定位置、产品材料/补充图片组、DWG 附件和资料包导入导出；详情采用统一右侧停靠轨道，批量移位需要筛选结果确认。旧借出、归还、维修、保养、状态和履历交互已删除。

第二轮复审修正：仓库详情、库存流水和任务日志的异步请求都必须绑定对象 ID（仓库额外包含物品类型）与递增请求代次；传输层支持 `AbortSignal`，只有对象仍打开且请求代次最新时才写入 data/error/loading，避免慢响应覆盖新对象。模具详情现已接入统一右侧停靠轨道，图片和 DWG 请求按模具 ID 加载，删除和资料包提交期间使用提交锁与二次确认。

第三批（2026-08-26）完成系统通用列表和更新中心视觉迁移。客户端优先整改已以自动发现启动页替代旧的登录后服务器测试/保存 UI；通用模块继续共享 `PageHeader`、`FilterBar`、`PageState`、`DataTableShell` 和 `StatusTag`。

第三批独立审查修正：启动连接与登录请求绑定服务器地址和认证代次，切服或退出会使旧结果失效，`/auth/me` 失败必须清除本地 token 和当前用户并返回登录。角色/权限配置项使用独立于页面列表的全量分页缓存，Dialog 在成功取得完整选项前展示 loading/error/retry 并禁止保存；审计展示真实 `account_type` 和完整操作时间。更新中心区分加载、请求错误、更新源错误和停用状态，刷新与立即检查共享互斥和请求代次。

第三批终审修正：更新服务明确返回 `enabled=false` 时，停用状态优先于连通性和历史错误，统一显示 info“更新检查已停用/已停用”；立即检查按钮与方法同时禁用，并提示需由服务端开启。权限配置按权限编码前缀和规范化对象路径归并为系统管理、仓库、任务、模具、客户等可读业务域，未知域使用可读兜底，不直接把 API 路径作为分组标题。角色或权限新增成功后必须清除对应的全量配置项缓存，下次打开配置 Dialog 重新分页加载，避免遗漏新项。

Windows 客户端更新在桌面端首页与更新中心复用同一全局任务：`Idle → Checking → Ready → Downloading → Verifying → Applying → Restarting` 映射为检查、下载、校验、安装、重启五个用户阶段。Applying/Restarting 同时禁止遮罩、Escape、模块切换、退出、切服、刷新和标题栏关闭。客户端与服务端直接使用本版本已确认的自动更新契约。

后续 UI 固定流程：新功能或接口契约变化后，先更新本文件实施进度与受影响状态；主代理锁定契约，`ui_designer` 输出只读规范，`web_frontend` 实现；主代理完成测试、构建和可行的真实浏览器检查；`ui_reviewer` 独立审查并退回所有 P0/P1；技术/UI 通过后由 `product_manager` 终审，最后由项目负责人完成成品验收。Web build、Client 前端 build、Tauri 运行、Windows/WebView2 和生产验收分别记录，不能互相替代。
