# 客户模块业务与数据规则

## 数据关系

客户模块由稳定的客户编码和可变的客户资料组成：

```text
CustomerCode（客户编码） 1 ── N CustomerProfile（客户资料）
```

客户编码使用自增 ID 和唯一 `BB-` 编码；客户资料包含简称、名称、地址、电话、联系人、联系人电话、业务员及默认标记。联系人和联系电话只是一条资料中的单组字段，不再存在独立联系人模块。

客户编码是后续送货单、开票和月/年订单统计的业务锚点。本期库存单、任务单和模具继续使用字段名 `customer_id`，但值统一是具体 `CustomerProfile.ID`；选择项显示编码加简称/名称，并标识默认资料。统计中的“客户总数”按 `CustomerCode` 数量计算。

## 编码与默认资料

- 输入 `1`、`BB-1`、`bb-001` 均保存为 `BB-001`；数字必须大于零且至少显示三位。
- 自动编号取数据库中最大数字加一，不回填缺号；并发冲突由唯一索引和有限重试处理。
- 编码允许暂时没有资料。
- 首条资料自动成为默认；追加第二条不改变默认。
- 有资料时必须且只能有一条默认资料。数据库条件唯一索引保证“最多一条”，服务事务保证“至少一条”。
- 删除仍有同码其他资料的默认资料时，必须选择替代资料；切换和删除在同一事务完成。
- 资料创建后不能更换编码，关联错误通过删除并重新创建处理。

## 删除与权限

客户编码和客户资料均为物理删除。编码有关联资料时不能删除；资料被库存单、任务单或模具引用时返回 `409`，历史业务记录即使软删除仍视为引用。新数据库同时使用指向 `customer_profiles.id` 的 `ON DELETE RESTRICT` 外键防止历史引用悬空。删除不可恢复，界面必须明确提示影响。

- `customers:read`：查看、选择项、Excel 模板、导出预览与下载。
- `customers:write`：编码和资料 CRUD、默认资料切换。
- `customers:import`：Excel 校验预览与确认导入。

全新数据库只初始化上述权限，不初始化旧 `contacts:*` 权限。

## 部署边界

本实现只保证全新 SQLite 数据库初始化与运行，不包含旧表检测、旧字段转换、旧客户/联系人数据迁移、旧表清理或双轨兼容。部署前如存在历史客户数据，应继续使用旧版本或单独立项制定经业务确认的数据迁移方案。
